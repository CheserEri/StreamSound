# StreamSound 路线图

## 1. 目标

做一个完全自托管、可离线运行的个人音乐串流系统：

- 服务端扫描本地音乐目录，提供检索、收藏、历史、串流与封面
- 桌面客户端以“本地音乐播放器”的方式操作，界面采用莱茵生命终端风格
- 不依赖任何在线音乐平台、账号或 CDN

## 2. 首版范围（曲库核心版）

已确定并交付的能力：

- 账号密码登录与服务端 JWT 会话
- 音乐目录扫描、标签与封面解析、全文检索
- 搜索曲目 / 喜欢的歌曲 / 文件夹 / 播放历史四栏目
- 收藏、取消收藏、播放历史上报
- HTTP Range 串流、进度拖动、音量与切歌
- 封面与主色、LRC 歌词同步
- 桌面端桥接进程、本地媒体代理、DPAPI 凭据存储

明确不在首版范围：

- 多用户社交、公开分享、评论
- 在线音乐平台抓取、歌词翻译
- 歌手 / 专辑 / 歌单 / 推荐栏目（服务端没有对应模型，界面仅占位）
- 移动端与 Web 端
- FSR3/帧生成（构建期可选，默认关闭）

## 3. 关键决策

| 编号 | 决策 | 结论 |
| --- | --- | --- |
| D1 | 媒体传输协议 | 使用现有 HTTP + Range，不引入 SMB |
| D2 | 前端技术栈 | 放弃 Compose/Salt UI，桌面端优先 |
| D3 | 桌面端实现 | Fork Rhine Music Database 的 Qt 6 + RHI 工程，保留 UI/3D 视觉 |
| D4 | 数据接口 | 桥接进程直接调用 StreamSound HTTP API，不保留 NetEase 适配层 |
| D5 | 登录方式 | 账号密码；令牌只存在桥接进程与 DPAPI 文件中 |
| D6 | 栏目映射 | 五槽位映射为搜索、收藏、文件夹、历史、不可用 |

## 5. 后续工作

1. 在目标机器上完成人工验收：真实账号登录、播放/切歌、歌词滚动、封面主色、收藏红心。
2. 发行包接入官方 Node 独立分发（`RHINE_NODE_BINARY` + `RHINE_NODE_LICENSE`），避免依赖系统 Node。
3. Windows 安装器与 macOS 包体走 `desktop/scripts/build.cjs` 统一产出。
4. 如需 FSR3，初始化 `desktop/.gitmodules` 中的子模块并打开 `RHINE_ENABLE_FIDELITYFX`。
5. 补充服务端扫描失败、文件删除、重复曲目等边界场景的自动化测试。

## 6. 版本与发布

- 采用语义化版本 `MAJOR.MINOR.PATCH`；桌面端版本由 `RHINE_VERSION` 注入
- 服务端 API 保持向后兼容；破坏性变更提升 `MAJOR`
- 发布记录以 Git 提交历史为准，不再单独维护 CHANGELOG
- 桌面端每次发布必须同步更新 `desktop/NOTICE` 中的第三方组件与许可

# StreamSound · 错误处理规范

---

## 1. 设计原则

- **播放不中断优先**：网络抖动、接口异常不应打断正在播放的音频，静默重试优先于弹窗打扰
- **错误分级处理**：轻微错误静默处理，严重错误才打断用户
- **明确告知，不甩锅**：提示语面向用户，不暴露技术细节（不出现 `500`、`ECONNREFUSED` 等）
- **可恢复操作必须给出出路**：每个 Modal 弹窗都要有明确的操作按钮，不能只有"确定"

---

## 2. 错误分级

| 级别 | 定义 | UI 行为 | 示例 |
|------|------|---------|------|
| **L1 静默** | 不影响用户当前操作，可自动恢复 | 无 UI，后台处理 | 播放历史上报失败、封面加载失败 |
| **L2 提示** | 操作未能完成，但不影响核心流程 | Modal 弹窗，单个「知道了」按钮 | 收藏失败、搜索无结果 |
| **L3 阻断** | 核心功能无法使用，需用户介入 | Modal 弹窗，带操作按钮，不可关闭 | 服务器无法连接 |
| **L4 崩溃兜底** | 未预期异常，客户端即将崩溃 | 全屏错误边界页面 | C++ 未捕获异常、Qt 致命错误 |

---

## 3. 网络与连接错误

### 3.1 服务器无法连接

**触发场景**：App 启动时、或业务请求连续失败 3 次后，判定服务器不可达。

**处理流程**

```
发起请求
    │
    ├── 超时（> 8 秒）或 Network Error
    │       │
    │       └── 静默重试，间隔 2s / 4s / 8s（指数退避，共 3 次）
    │               │
    │               ├── 重试成功 → 继续正常流程
    │               │
    │               └── 3 次均失败 → L3 Modal 弹窗
    │                       标题：「无法连接到服务器」
    │                       内容：「请检查手机与服务器是否在同一网络，或确认服务器地址是否正确。」
    │                       按钮：[去设置]  [重试]
```

**播放中断网的特殊处理**

音频流中断时（Qt Multimedia 解码错误或本地代理 HTTP 读取失败），不弹 Modal，执行以下逻辑：

```
音频流中断
    │
    └── 静默重试（最多 5 次，间隔 3s）
            │
            ├── 重试成功 → 从断点位置恢复播放，无任何 UI 提示
            │
            └── 5 次失败 → L2 Modal
                    标题：「播放中断」
                    内容：「无法加载音频，请检查网络连接。」
                    按钮：[知道了]
                    （播放器停止，保留当前队列和进度）
```

### 3.2 请求超时阈值

| 请求类型 | 超时时间 |
|---------|---------|
| 普通 API 请求 | 8 秒 |
| 音频流首包 | 10 秒 |
| 封面图加载 | 5 秒（失败显示占位图，不提示） |
| 扫描触发 | 5 秒（仅等待 202 响应） |

## 4. 业务功能错误

### 4.1 收藏 / 取消收藏失败

| 错误码 | UI | 提示内容 |
|--------|-----|---------|
| `FAV_001` | L2 Modal | 「该曲目不存在，可能已被从音乐库中移除。」|
| `FAV_002` | L1 静默 | 已在收藏中，UI 状态保持为已收藏即可 |
| `FAV_003` | L1 静默 | 不在收藏中，UI 状态保持为未收藏即可 |
| 网络失败 | L2 Modal | 「收藏失败，请检查网络连接后重试。」|

> 收藏按钮点击后应立即更新本地 UI 状态（乐观更新），请求失败时回滚状态并弹 Modal。

### 4.2 播放历史上报失败

**处理**：L1 静默，不重试，不提示。历史记录非核心功能，丢失单条无影响。

### 4.3 搜索失败

| 场景 | 处理 |
|------|------|
| `SEARCH_001`（关键词为空） | 不发起请求，输入框无变化 |
| 网络失败 | 搜索结果区显示内联文字「搜索失败，请检查网络」，不弹 Modal |
| 无结果（正常 200，空数组） | 显示「未找到相关结果」占位图，非错误状态 |

### 4.4 音乐库加载失败

| 场景 | UI | 提示 |
|------|----|------|
| 文件夹列表加载失败 | L3 Modal | 「无法加载音乐库，请检查服务器连接。」[重试] |
| 曲目列表加载失败 | 页面内 inline 提示 + [重试] 按钮 | 不影响其他页面 |
| 单曲详情加载失败 | L2 Modal | 「无法获取曲目信息。」[知道了] |

### 4.5 扫描操作失败

| 错误码 | UI | 提示 |
|--------|-----|------|
| `SCAN_001`（扫描进行中） | L2 Modal | 「音乐库正在扫描中，请稍后再试。」|
| `SCAN_002`（路径无效） | L2 Modal | 「音乐文件夹路径无效或不存在。」|
| 扫描触发网络失败 | L2 Modal | 「触发扫描失败，请检查网络连接。」|

## 5. 服务端错误（5xx）

所有 5xx 错误统一处理，不区分具体状态码：

**UI**：L2 Modal（播放中为 L1 静默重试）

```
标题：「服务器暂时无法响应」
内容：「请稍后重试，如果问题持续存在，请检查服务器状态。」
按钮：[知道了]
```

---

## 6. 全局错误边界（L4）

客户端为 Qt/C++，L4 对应未捕获异常或 Qt 致命错误。目标方案是在 `main()` 安装 `qInstallMessageHandler` 与 `std::set_terminate`，将堆栈、当前视图写入本地日志，并向用户展示可重新启动的兜底页。

**触发时**显示全屏兜底页：

```
[图标]
「出了点问题」
「应用遇到了未知错误。」
[重启应用]
```

同时将错误信息（错误堆栈、当前视图）写入应用数据目录下的 `crash.log`，便于随安装包反馈排查。

## 7. 错误提示文案规范

| 正确写法 | 错误写法 |
|---------|---------|
| 「无法连接到服务器，请检查网络。」 | 「Network Error: ECONNREFUSED」 |
| 「无法获取曲目信息。」 | 「404 Not Found」 |
| 「收藏失败，请稍后重试。」 | 「POST /favorites/101 failed」 |
| 「服务器暂时无法响应。」 | 「500 Internal Server Error」 |

**原则**：
- 描述"发生了什么"，而不是"哪里出错了"
- 告知用户"能做什么"（检查网络 / 稍后重试）
- 不超过 40 字，不用感叹号

## 8. 前端实现要点

### 8.1 ApiClient 职责

```
请求阶段：使用配置的服务器地址发起请求，不附加任何认证信息
响应阶段：
  - 网络错误    → 抛出标准化 AppError，由业务层决定如何展示
  - 其他错误    → 抛出标准化 AppError，由业务层决定如何展示
```

### 8.2 标准化错误对象

```kotlin
data class AppError(
    val code: String,        // 来自服务端的错误码，如 "LIB_002"
    val message: String,     // 面向用户的提示文案
    val httpStatus: Int      // HTTP 状态码，用于分级判断
)
```

### 8.3 重试工具函数

```kotlin
// 指数退避重试，适用于网络请求和音频流重连
suspend fun <T> withRetry(
    maxAttempts: Int = 3,
    baseDelayMs: Long = 2000,
    block: suspend () -> T
): T
```

### 8.4 ErrorModal 组件规范

全局使用统一的 `ErrorModal` 组件，避免各页面自己实现弹窗样式：

```kotlin
data class ErrorModalProps(
    val title: String,
    val message: String,
    val primaryAction: Action,
    val secondaryAction: Action? = null,
    val dismissable: Boolean = true // false 时点击蒙层不关闭（L3 阻断场景）
)
```

- 最多两个按钮：主操作（实心）+ 次操作（描边）
- L3 阻断场景：`dismissable={false}`，不提供关闭手势
- L2 提示场景：`dismissable={true}`，点击蒙层可关闭
